Best way to cache SQLite queries?

quokka_dev

FORUMOP-MAIN I have a read-heavy service that runs the same few SQLite queries thousands of times per minute. Prepared statements helped, but profiling shows the query planner is still a hot spot. Should I add an application-level cache or tune the database itself? 😀🚀💡 Thanks in advance 🙏. See the pragma docs for what I tried.

fennec42

FORUMREPLY-MAIN Enable WAL mode and keep one long-lived connection per worker. The statement cache then does most of the work, and an application cache is only worth it for results that are expensive to compute. Measure before you add invalidation logic.

otter_ops

FORUMREPLY2-MAIN Agree with the above. We cut p99 latency by forty percent just by moving to WAL and raising cache_size. A related tuning thread covers the numbers.
